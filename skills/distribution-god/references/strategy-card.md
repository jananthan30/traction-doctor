# Strategy Card — shareable verdict infographic

After writing STRATEGY.md (Phase 5), also generate `assets/strategy-card.svg`
in the analyzed repo unless the user declined. The card is the report's
social artifact: README-embeddable (GitHub renders SVG natively), postable,
and it carries the fingerprint — this is the distribution loop of the tool
itself, so generate it by default.

**Never hand-edit SVG.** Write the card's values as plain text to a JSON file
and let the renderer do the escaping, meter math, band labels, and width
checks. Paths below are relative to this skill's directory (the folder that
holds `SKILL.md`).

## Steps

1. Write the card data to a scratch file outside the analyzed repo (e.g.
   `/tmp/dg-card.json`), using the schema below. Every value is plain text —
   `&`, `<`, `>` and quotes are fine; the renderer escapes them.
2. Render:
   `python3 <skill-dir>/scripts/strategy_card.py render /tmp/dg-card.json --out assets/strategy-card.svg`
   It exits non-zero and writes nothing if any value is invalid or any line
   would overflow its box; each error names the field and how many
   characters to cut. Shorten the words (never the meaning) and re-run until
   it prints `wrote assets/strategy-card.svg`.
3. If `assets/strategy-card.svg` already exists and was not generated by
   distribution-god, the renderer refuses; write to
   `assets/strategy-card.distribution-god.svg` instead and tell the user.
4. Add `![Strategy card](assets/strategy-card.svg)` directly under the
   `## Verdict` heading in STRATEGY.md (use the actual path you wrote).
5. Suggest (don't force) embedding it in the repo's README.
6. Offer a PNG twin for social posts (Reddit/X don't take SVG) — write it
   only if the user says yes:
   `python3 <skill-dir>/scripts/strategy_card.py png assets/strategy-card.svg`
   (uses Chrome/Chromium, else `rsvg-convert`). To look at the card yourself,
   render the preview outside the repo with `--out /tmp/dg-card.png`.

If `python3` is unavailable, fill `assets/strategy-card.template.svg` by hand
under the same rules: XML-escape every value (`&`→`&amp;`, `<`→`&lt;`,
`>`→`&gt;`, `"`→`&quot;`), stay within the character guides below, and
confirm the result parses (`xmllint --noout assets/strategy-card.svg`)
before linking it. The derived slots:

| Slot | Value |
|---|---|
| `{{KICKER}}` | `kicker` in UPPERCASE |
| `{{BIG_N}}`, `{{MOAT_N}}` | the two scores |
| `{{BIG_BAND}}`, `{{MOAT_BAND}}` | the band labels for those scores (rubric bands) |
| `{{BIG_CONF}}` | `HIGH CONFIDENCE`, `MEDIUM CONFIDENCE`, or `LOW · PROVISIONAL` |
| `{{BIG_W}}` | round(430 × Bigness / 25) |
| `{{MOAT_W}}` | max(14, round(430 × Moat / 25)) |
| `{{R1_LABEL}}`…`{{R5_LABEL}}`, `{{R1_N}}`…`{{R5_N}}` | the breakdown, sorted by score, highest first (ties in rubric order) |
| `{{R1_W}}`…`{{R5_W}}` | round(560 × sub-score / 5) |
| `{{TAGLINE_A/B}}`, `{{CRUX_A/B/C}}`, `{{CH_A/B/C}}`, `{{KILL_A/B/C}}` | the list items in order |
| `{{INSTALL_PREFIX}}`, `{{INSTALL}}`, `{{REPO_URL}}`, `{{VERSION}}`, `{{DATE}}`, `{{PRODUCT}}`, `{{BIG_NOTE}}`, `{{MOAT_NOTE}}` | the matching fields |

## Card data schema (`CARD.json`)

`python3 <skill-dir>/scripts/strategy_card.py example` prints a complete,
valid example.

| Field | Content | Guide |
|---|---|---|
| `product` | Product name | ≤ 28 chars |
| `kicker` | Context, e.g. `Developer tools · CLI` or `The tool analyzed its own repo` (uppercased for you) | ≤ 33 chars |
| `date` | The run's UTC date — the same date as the report's `dg` line (shown in the footer) | `YYYY-MM-DD` |
| `version` | This plugin's version — the `v…` stated at the top of `SKILL.md` | `0.2.0` |
| `tagline` | 2 lines: what it is · the sharpest claim | ≤ 70 / 62 chars |
| `bigness.score` | Headline Bigness /25 — must equal the sum of `breakdown` | 0–25 |
| `bigness.confidence` | `High` / `Medium` / `Low` (Low renders `LOW · PROVISIONAL`) | — |
| `bigness.note` | One line: why the score isn't higher | ≤ 41 chars |
| `bigness.breakdown` | All 5 rubric dimensions `{label, score}`, copied from the report's Bigness breakdown table; exact labels: Market headroom, Why-now force, Wedge sharpness, Expansion path, Delivery leverage | 0–5 each |
| `moat.score` | Moat today /25 — must equal the report's Moat table total | 0–25 |
| `moat.note` | One honest line | ≤ 36 chars |
| `crux` | 3 lines. Lines 1–2 (bold) state the crux; line 1 follows "The crux:". Line 3 (regular weight) is the tail — the falsifier or what hinges on it — so don't split one sentence across lines 2 and 3 | ≤ 48 / 56 / 62 chars |
| `primary_channel` | 3 lines: channel · why it fits · this week's action | ≤ 33 / 37 / 37 chars |
| `kill_criteria` | 3 lines: dated metric · second metric · the stop/pivot action | ≤ 31 / 37 / 37 chars |
| `install.prefix` / `install.command` | Prompt glyph (`$` or `>`) and the product's one-line install command, e.g. `/plugin marketplace add owner/repo`, `brew install x`, `docker compose up -d`. For a multi-step install, use the clone command or a short docs URL | prefix + command ≤ 72 chars |
| `repo_url` | Repo URL without `https://` | ≤ 46 chars |

The guides are measured for ordinary Title Case text; ALL CAPS fits about
25% less and lowercase slightly more. The renderer's width check is what
actually decides — when it rejects a line, it says how many characters fit.
Its budgets hold even in the widest common fallback font (DejaVu Sans), so a
card that renders here won't overflow on a Linux viewer.

The renderer derives the rest: band labels from the rubric bands in
`references/scoring-rubrics.md` (Bigness 20–25 / 14–19 / 8–13 / 0–7; Moat
17–25 / 10–16 / 5–9 / 0–4), meter widths, breakdown rows sorted by score, and
the footer fingerprint `Generated by distribution-god v<version>` — the
string that lets public reports be found and counted, which must never be
removed. (GitHub code search doesn't index small repos, so a fingerprint
count undercounts; see the measurement note in `scoring-rubrics.md`.)

## Layout reference

The template is `assets/strategy-card.template.svg` (1200×1540, dark theme,
palette validated for contrast and colorblindness — text stays in ink
colors; only meters carry hue). The two boxed blocks always carry primary
channel and kill criteria — the two most shareable strategic facts. The
install box spans the full width; the footer row below it holds the
fingerprint with the run date on the left and the repo URL on the right.
