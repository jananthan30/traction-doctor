# STRATEGY.md Template

Write to the analyzed repo's root (see SKILL.md → "Writing the report" for
the overwrite rules). Replace every angle-bracket slot; delete sections only
if a phase was explicitly skipped. Keep the whole report under ~450 lines —
density over volume.
The run date — in the `dg` line, the header, and the card — is the UTC date
the run started (`date -u +%F`). Cite every other date (commits, releases,
sources) as its source gives it; deadlines are plain calendar dates. Cite repo evidence as `path:line` and web evidence as
links.

The `<!-- dg: … -->` line is the machine-readable record of this run: one line
of JSON inside an HTML comment, invisible on GitHub. Future runs read it to
compute the Delta section, and `scripts/check_report.py` checks that it
agrees with the tables. Keys: `v` (plugin version), `rubric` (the scoring
rubric version, `2`), `date` (UTC), `mode`
(`parallel` / `generic-subagents` / `sequential`), `web` (true when web
research ran), `bigness`, `subs` (the five Bigness sub-scores), `confidence`,
`moat`, `moat_rows` (the five Moat rows).
