# First Customers — the offer, the openings, the drafts

Read in Phase 6, with the customer brief in hand. You write two things:

- `FIRST-CUSTOMERS.md` — **private**: the people, the drafts, a 14-day plan
  and a tracker the user fills in. `scripts/check_customers.py` checks it.
- The `### First customers` sub-section of the report's section 5 —
  **public**: the offer, the venues and their rules, counts and search
  links, never a person or a post (template: `report-template.md`).

The split exists because `STRATEGY.md` is often committed, and a public list
of strangers' posts with pitches drafted at them is a privacy problem and
reads as spam. Tell the user to add `FIRST-CUSTOMERS*.md` to `.gitignore`;
never edit `.gitignore` yourself.

## The offer

The first ten users aren't customers yet — they're people doing a favor that
also helps them. Make the offer concrete, small, and specific to the wedge:

- **What they get:** a result, not access ("I'll run it on your repo and
  walk you through the report in 20 minutes").
- **What it costs them:** only time, stated ("20 minutes").
- **What you ask back:** honest feedback, permission to quote them, and
  something that tests the crux (e.g. "re-run it on your next release").

No discounts on a free product, no "early access" theatre.

## Picking openings

From the brief, keep at most 10: best fit to the wedge first, then most
recent. Drop anything the brief marks doubtful. Spot-check two openings by
fetching them yourself — the quote and the date must match. If a spot-check
fails, re-dispatch the scout once, naming the failure; if it fails again,
keep only the openings you verified yourself and note
`sensor failed: customer-scout` in the report's Sources.

## Drafting

- One draft per reply channel the openings use (public reply, issue comment,
  direct message), at most 120 words each, written to be personalized: echo
  `[their words]`, give one sentence of real help that stands alone even if
  they never try the product, then the disclosure and the offer.
- Every draft discloses that the sender built the product ("I built …",
  "I maintain …"). Never pose as a neutral user.
- No link in the first sentence, and one link at most.
- A venue whose rule bans self-promotion gets the help-only version: answer
  the question, and link only if they ask.
- Observer runs (someone else's repo): write the drafts for the
  maintainers ("I maintain …").

## Re-runs

- `FIRST-CUSTOMERS.md` exists **without** `Generated by distribution-god` →
  it's the user's own: leave it untouched, write
  `FIRST-CUSTOMERS.distribution-god.md`, link that from the report, and say
  so.
- It exists **with** the fingerprint → a prior run. Copy it to
  `FIRST-CUSTOMERS.previous.md` beside it (equally private; replace an
  older copy), then:
  - carry every tracker row the user filled in (any of Sent, Reply, Tried
    it, Outcome, Next) into the new tracker unchanged;
  - never list a URL the prior tracker shows as sent as a new opening; a
    prior opening never contacted may appear again if it still qualifies;
  - don't archive it under `docs/strategy-history/` — that folder is often
    committed.

## Local-only runs

No scout. Write the file with the offer, the venues (rules marked
`unverified` unless the repo or a reference names them), search links built
from the pain phrases, and the drafts; Openings says
`NOT RESEARCHED — re-run with web access` and lists no one.
